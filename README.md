# FastAPI Lab: Wine Cultivar Classifier API

A FastAPI service that predicts which of three grape varieties (cultivars) a wine was made from,
using 13 chemical measurements. It returns the predicted cultivar with probabilities, accepts
batches, rejects impossible inputs with clear errors, and reports how the model scored on test data.

Based on [API_Labs/FastAPI_Labs](https://github.com/raminmohammadi/MLOps/tree/main/Labs/API_Labs/FastAPI_Labs)
from the MLOps course repository, which serves a decision tree trained on the Iris dataset.

## What I changed

| | Original lab | This version |
|---|---|---|
| Data and model | Decision tree on Iris (4 measurements), never evaluated: the test split is created and then unused | scikit-learn's wine dataset (13 measurements, 178 wines). A scaler and logistic regression in one pipeline, scored on held-out wines: **98.15%** test accuracy, against 94.44% for the original's decision tree on the same split |
| Saved results | Only the model file | `train.py` also writes `model/metrics.json`: test accuracy, confusion matrix, training date and scikit-learn version |
| Loading the model | Loaded from disk on every request, from a path that only works when started inside `src/` | Loaded **once at startup** (FastAPI `lifespan`), from an absolute path, so it works from any folder. A missing model stops the server with a clear message |
| Prediction output | A class number: `0`, `1` or `2` | The cultivar name, its probability, and the probability of every cultivar |
| Endpoints | `GET /` and `POST /predict` | Also `POST /predict/batch` (1–100 wines) and `GET /model-info` |
| Input checks | Any number is accepted | Each measurement has limits (wider than anything in the dataset), unknown fields are rejected, and an empty batch is rejected, all with a 422 explaining what's wrong. The `/docs` page shows a real wine as the example request |
| Tests | None | 9 pytest tests using FastAPI's `TestClient`, including one that checks every wine in the dataset passes the input limits |

Smaller changes:

- Fixed the original README's run command: `uvicorn app:main` should be `uvicorn main:app`.
  Here it is `uvicorn src.main:app`, run from the project root.
- Prediction endpoints are plain `def` instead of `async def`. Prediction is CPU work, and FastAPI
  runs plain functions in a thread pool, so one prediction doesn't hold up other requests.
- Pinned current versions in `requirements.txt` (FastAPI 0.165, scikit-learn 1.9.1). The saved model
  must be loaded with the same scikit-learn version it was trained with.

## The model

The [wine dataset](https://scikit-learn.org/stable/datasets/toy_dataset.html#wine-recognition-dataset)
is a chemical analysis of 178 wines grown in the same region of Italy, made from three cultivars
(59, 71 and 48 wines). The 13 measurements include alcohol, malic acid, magnesium, flavanoids,
colour intensity, hue and proline.

The measurements are on very different scales (hue is around 1, proline is in the hundreds),
so a `StandardScaler` puts them on the same scale before the logistic regression. Both are saved
together in `model/wine_model.pkl`, so the API takes the raw measurements.

The model trains on 70% of the wines (124) and is scored on the other 30% (54).

## API

| Method | Path | What it does |
|---|---|---|
| `GET` | `/` | Health check: `{"status": "healthy"}` |
| `GET` | `/model-info` | The model, training date, scikit-learn version, test accuracy, confusion matrix, classes and features |
| `POST` | `/predict` | One wine's 13 measurements → the predicted cultivar and probabilities |
| `POST` | `/predict/batch` | `{"samples": [...]}` with 1–100 wines → one prediction per wine |
| `GET` | `/docs` | Interactive documentation generated by FastAPI, where you can try every endpoint |

## Project structure

```text
.
├── requirements.txt
├── model/
│   ├── wine_model.pkl      # the trained pipeline (scaler + logistic regression)
│   └── metrics.json        # test results, written by train.py
├── src/
│   ├── data.py             # loads and splits the wine dataset; feature and class names
│   ├── train.py            # trains, evaluates and saves the model and metrics
│   ├── predict.py          # loads the model and turns its output into labels and probabilities
│   └── main.py             # the FastAPI app: input limits, endpoints, startup loading
└── tests/
    └── test_api.py         # 9 tests for the API
```

## Running it

Requires Python 3.11 or newer.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python -m src.train                  # optional: the trained model is already in model/
uvicorn src.main:app --reload        # start the API on http://127.0.0.1:8000
```

Open <http://127.0.0.1:8000/docs>, pick an endpoint, click **Try it out**, then **Execute**.
`/predict` is pre-filled with a real wine from the dataset.

Or from a terminal:

```bash
curl -X POST http://127.0.0.1:8000/predict -H 'Content-Type: application/json' -d '{
  "alcohol": 14.23, "malic_acid": 1.71, "ash": 2.43, "alcalinity_of_ash": 15.6,
  "magnesium": 127, "total_phenols": 2.8, "flavanoids": 3.06, "nonflavanoid_phenols": 0.28,
  "proanthocyanins": 2.29, "color_intensity": 5.64, "hue": 1.04,
  "od280_od315_of_diluted_wines": 3.92, "proline": 1065}'
```

Run the tests from the project root:

```bash
python -m pytest -v
```

## FastAPI ideas used

- **Pydantic models** (`WineSample`, `Prediction`, `BatchRequest`) describe the request and response
  bodies. FastAPI checks every request against them and returns a 422 with details when it doesn't fit.
- **`Field` limits** (`ge`, `le`, `min_length`, `max_length`) and `extra="forbid"` do the input checks.
- **`response_model`** shapes each response and documents it on the `/docs` page.
- **`lifespan`** runs code once when the server starts and stops; here it loads the model.
- **`TestClient`** calls the app in tests without starting a real server.
